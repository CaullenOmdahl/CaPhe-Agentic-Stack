# Abstraction — <component/system>

## Goal

State the observable outcome without implementation detail.

## Surfaces

Actors, interfaces, outputs, and affected systems.

## Actions

Triggers and operations.

## State and data

Authoritative, derived, retained, and deleted state.

## Rules

Tag each behavior `intended`, `legacy`, `unknown`, or `rejected`.

## Edge cases

Boundaries, failure, concurrency, ordering, and recovery.

## Non-functional targets

Performance, determinism, privacy, security, observability, and portability.

## Approval and open questions

Record named gates. Unknowns that change outcomes block implementation.
