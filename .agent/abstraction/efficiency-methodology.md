# Evidence-preserving workflow runtime

The actor is an agent continuing or implementing authorized work in a repository. It needs bounded,
source-bound evidence and exact outstanding acceptance before deciding the next action. The terminal
state is independently reviewed work with complete verification and an auditable installed methodology.

Acceptance:

- Context and history projections have a total byte bound, explicit truncation, stable source identity,
  and recoverable references. Failed commands and unresolved findings remain visible.
- Public evidence accepts only declared public fields, preserves immutable history, and distinguishes
  implementation, validation, review, merge, release, and external acceptance. Private continuation and
  authorization remain owner-only outside Git worktrees.
- Environment diagnosis is read-only. Preparation and installation are explicit, idempotent operations
  that preserve project rules, unrelated working changes, existing hooks, manifests, and private state.
- Feedback considers the actual working snapshot and only narrows through proven dependencies. Full
  completion remains uncached and exhaustive. Candidate-generated CI reports cannot certify themselves.
- Model and effort are explicit, capability-checked, and evaluated by task class. Unknown usage cannot
  support cost claims. Unqualified routes retain the incumbent; lossy compression stays off by default.
- Semantic acceptance binds the observable display contract and artifact/device scope. Validation alone
  does not establish visual or hardware correctness.
- Rollout verifies deployed source identities and each target's activation, and records precise exceptions
  privately. A project lacking verified activation must not be reported upgraded.

Use the smallest standard-library runtime and existing strict-mode planner/evidence tools. The rollout
changes agent methodology, not application behavior, deployments, customer data, or canonical memories.
